# BRIEF: bootstrap-decisions (фаза 0)

Дата: 2026-07-31

## Формулировка своими словами

Перед первой строкой прикладного кода нужно зафиксировать архитектурные и продуктовые решения для Doge Rescue: стек, структуру репозиториев, стратегию i18n и границы MVP. Текущий репозиторий `dogrsc` остаётся координирующим (harness, спецификация, tasks); прикладной код пойдёт в отдельные репозитории. Результат фазы — согласованный набор решений в DECISIONS и обновлённая карта проекта, без scaffold и без деплоя.

## Контекст

- Спецификация: PDF «Doge Rescue Website Structure and Management System» (47 стр.), разделы 20–31, 27 (i18n).
- Карта: `harness/PROJECT.md` — код отсутствует, часть решений помечена как TODO или противоречит Known issues.
- Harness: цикл BRIEF → PLAN (утверждение человеком) → СДЕЛАТЬ → REPORT.
- Репетиция плана уже проведена; пользователь уточнил:
  - **Языки MVP:** en, th, ru — все три с первого дня.
  - **Репозитории:** отдельные, не монорепо.
- Git: ветка `main`, коммитов может не быть; remote не обязателен на этом шаге.

## Открытые вопросы

| Вопрос | Статус |
|--------|--------|
| Admin UI: только en или тоже th/ru? | **Предложение для MVP:** UI админки на en; редактирование контента сайта — поля/формы для en, th, ru. Отложить локализацию интерфейса админки, потому что аудитория — staff, а не публика. |
| Отдельный репо `dogrsc-contracts`? | **Решение:** нет; OpenAPI (`openapi.yaml`) живёт в `dogrsc-backend`, артефакт CI. Отдельный репо — только если codegen из нескольких источников станет узким местом. |
| S3-провайдер (п.3)? | **Предложение:** Cloudflare R2. Финальное подтверждение — при задаче infra; для фазы 0 достаточно записи «R2 (рекомендация)». |
| Создание репо на GitHub/GitLab? | **Закрыто:** не создаём remote; локальные репо — при scaffold. |
| Backend NestJS vs Django в Known issues PROJECT.md | **Закрывается этой фазой:** NestJS. |
