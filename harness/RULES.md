# Правила работы

1. Перед любой задачей прочитай harness/PROJECT.md — карту проекта.
  Загляни в harness/LESSONS.md и harness/DECISIONS.md — возможно,
   похожая задача уже решалась или похожая ошибка уже случалась.
   Отвечай о проекте по карте; чего нет в карте и коде — говори прямо.
   Нашёл похожее — скажи об этом до начала работы.
2. Прежде чем создать функцию/компонент/файл — поищи существующий
  аналог в проекте. Нашёл похожее — покажи и спроси, точно ли нужно новое.
3. Прежде чем назвать причину бага — покажи доказательство (лог,
  воспроизведение, конкретная строка). Догадка без доказательства
   так и называется догадкой — словом «предполагаю».
4. Никаких молчаливых больших правок. Меняешь больше, чем просили, —
  сначала скажи, что и зачем собираешься менять.
5. После завершения задачи предложи записи для журналов:
  - принято решение с причиной → черновик строки в DECISIONS.md
  - была ошибка/сюрприз/неочевидность → черновик строки в LESSONS.md
   Если записывать нечего — скажи «нет решений, нет уроков».



## Создание задачи

Перед фазой «Понять» создай папку задачи скриптом (не вручную):

```powershell
python harness/new_task.py "название задачи"
```

Скрипт создаёт `tasks/<ГГГГ-ММ-ДД>-<slug>/` с BRIEF.md, PLAN.md, REPORT.md из `harness/templates/`. Не создавай эти три файла через редактор с нуля.

## Цикл задачи

Для любой нетривиальной задачи (больше ~30 минут или больше 1-2 файлов):

1. ПОНЯТЬ — заполни BRIEF.md в созданной папке по шаблону
  harness/templates/BRIEF.md. Не предлагай решение, пока критерии
   успеха не сформулированы. Открытые вопросы задавай человеку.
2. СПЛАНИРОВАТЬ — заполни PLAN.md по шаблону
  harness/templates/PLAN.md: проверяемые шаги, минимум одна
  отвергнутая альтернатива с содержательной причиной. Не начинай
   реализацию, пока план не утверждён человеком.
3. СДЕЛАТЬ - строго по плану
4. ЗАКРЕПИТЬ - заполни [REPORT.md](http://REPORT.md) по шаблону
  harness/templates/REPORT.md

Малый режим: мелочь (меньше ~30 минут, 1-2 файла) - без артефактов, сразу:

1. Задача начала расти, она перестала быть мелкой — создай папку через `new_task.py` и открой BRIEF задним числом
2. Сюрприз в мелкой задачи все равно идет в журнал уроков [LESSONS.md](http://LESSONS.md). Однострочный фикс вскрывший двойное
  чтение конфига обязан оставить запись



## Переходы между фазами

Не переходи к следующей фазе, пока не показал человеку выполненный
чек-лист выхода текущей фазы. Формат: процитируй чек-лист, отметь
каждый пункт ✅/❌, при ❌ — что не хватает. Пункт нельзя отметить ✅
без содержимого в соответствующей секции.

## Необратимые действия

Действия, которые нельзя отменить (деплой, удаление данных, отправка
сообщений людям, публикация, платежи), — всегда риск 🔴: требуют
явного подтверждения человека непосредственно перед выполнением,
даже если упоминались в утверждённом плане.

## Бюджет задачи

В PLAN назначается бюджет: файлов и времени. При превышении:
остановись и сообщи — «бюджет превышен: N файлов при лимите M,
вот почему». НЕ продолжай молча. Дальше решает человек:
расширить план или откатиться к границе бюджета.

## Репетиция

1. «Прорепетируй план» — до фазы «Сделать».
2. Каждое «НЕ УВЕРЕН» → проверить сейчас или явный риск в PLAN.
